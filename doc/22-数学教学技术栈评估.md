# 数学教学技术栈评估

日期：2026-10-30。依据用户提供的候选技术栈，结合第 01、14、19 号文档及当前实现。本文是选型建议，不表示已经安装、迁移或接入。

## 结论

保留 React + TypeScript + Vite、Hono、Cloudflare Workers / D1、Nova / Radix 和确定性数学引擎。候选技术按教学需求逐项增加，当前不迁移整套框架，也不同时添加多套动画或图形方案。

| 技术 | 当前决策 | 实际价值和引入条件 |
| --- | --- | --- |
| React + TypeScript | 已有并保留 | 组件、共享契约、数学状态与 API 校验继续沿用 |
| Next.js | 暂不迁移 | 当前任务是练习与交互教具。出现明确的服务端渲染、公开内容站等需求时，再单独核算路由、认证、D1、缓存与部署迁移成本 |
| Motion | 下一阶段优先试点 | 对象分组、进位、数轴移动、边界替换等需要连续变化时采用；普通按钮和提示仍用 CSS |
| GSAP | 暂不引入 | 不与 Motion 重叠承担主要动画能力。若将来 Motion 无法满足已验证的复杂时间轴需求，再评估替换与迁移，而不是并行添加 |
| KaTeX | 有复杂公式需求时优先评估 | 分数、上下标、多层算式需要统一排版时，通过一个共享公式组件接入；普通四则算式和图内短数值保留文本 |
| MathLive | 教师编辑端优先、学生端按题型引入 | 教师编辑公式、或学生必须输入分数/完整表达式时使用；不替换当前整数填空和结构化竖式输入 |
| SVG + JSXGraph | SVG 保留，JSXGraph 作为专项扩展 | 本轮图示继续 SVG；可拖动的几何约束、轨迹和函数联动达到现有模板难以维护的程度时，引入独立场景适配器 |
| Python + SymPy | 离线编审与校验候选 | 符号化简、解方程、等价性与批量内容核对可在编审工具中使用；首期整数判题继续现有 TypeScript 纯函数，不增加在线 Python 服务 |
| LLM + Structured Outputs | 编审草稿工具的后续建设 | 按固定题型生成受约束的步骤、理由和图示动作；通过 Schema、数学语义和人工审核后才发布，不能直接成为学生判题依据 |

## 优先试点的实现边界

### Motion：让同一个数学对象连续变化

先选择分组、单位进位或拼剪边界中的一个场景验证。图形节点需要稳定的语义 ID，不能以数组下标猜测哪个对象移动到了哪里。数学引擎决定起止状态和步骤；Motion 只在两种已验证的状态之间呈现移动、合并或高亮。

手动前后步、暂停、切题、关闭方法页必须停止相应动效，并落到完整有效的数学状态。减弱动效时直接显示完整状态；不通过任意插值数字表现整数份数或判题结论。

### KaTeX：先建立共享公式组件

区分普通文本公式和经过审核的 LaTeX 内容，统一字号、基线、行内/独立模式、无障碍输出与溢出行为。只在适合的题型加载，静态资源随项目打包，锁定精确版本。错误公式有文本回退，不让渲染失败阻断作答。

图示坐标和几何标注仍由 SVG 控制，不把整幅教具变成 LaTeX。与第 01 号文档一致，不开启对任意 HTML、链接或脚本的信任。

### AI 与 SymPy：结构化不等于正确

建议沿用现有架构基线：固定教材和题型 → LLM 结构化草稿 → Zod/Schema 验证 → 确定性数学核对（必要时离线 SymPy）→ 图示边界与步骤预览 → 人工审核 → 内容发布。

校验需要覆盖单位、数量关系、舍入适用条件、几何边界和错误反例，不能只核对最终数值。模型不输出可执行 JSX、脚本或自定义工具权限。开放证明、教案适龄性和解释质量不能因为通过 Schema 就视为自动验证成功。

## 当前开发的处理

本轮继续深化其余 40 类题型，补齐错图与订正图、分步依据和独立迁移判断。没有安装候选库，没有改动锁文件、线上运行时、D1、账号或判题协议。待内容与 PC/平板布局验收完成后，优先做一个 Motion 场景试点，再根据明确的公式需求接入 KaTeX。

## 官方资料

- [Cloudflare 的 Next.js 部署指南](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/)：当前指南推荐 vinext 路径，并单独保留 OpenNext 等路径；迁移时必须重新核对兼容性，不能直接照搬旧部署教程。
- [Motion for React](https://motion.dev/docs/react)：支持 React 组件及 SVG 动画，适合在现有 React 结构内按需接入。
- [KaTeX 浏览器文档](https://katex.org/docs/browser.html)：公式渲染需配套样式与字体资源。
- [MathLive React 集成](https://mathlive.io/mathfield/guides/react/)：通过 math-field 元素集成，需配套输入、焦点、键盘和 TypeScript 处理。
- [JSXGraph 文档](https://jsxgraph.org/docs/)：包含几何、交点、函数、滑块与轨迹等场景能力。
- [SymPy 文档](https://docs.sympy.org/latest/index.html)：提供符号运算、化简与求解等能力；是否用于在线链路需另行架构验证。
