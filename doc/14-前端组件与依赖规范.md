# 前端组件与依赖规范

日期：2026-10-21。适用于 PC Web 与平板浏览器。

## 选型与当前状态

优先复用成熟实现，统一设计语言，组件源码可维护。同类能力只保留一套主要依赖。以下选型确定后续方向，不代表已经安装或迁移完成。

| 能力 | 统一方案 | 当前状态与引入条件 |
| --- | --- | --- |
| 通用 UI | shadcn/ui Nova | 当前是共享 React 组件与 CSS；后续按组件迁移，源码集中到 `apps/web/src/components/ui/` |
| 图标 | Lucide / `lucide-react` | 已安装，现有 `components/ui.tsx` 统一封装图标；继续复用 |
| UI 动画 | Motion | 尚未安装；有复杂进入、退出或布局过渡时引入，简单反馈继续用 CSS |
| 可调整面板 | react-resizable-panels | 尚未安装；需要学生主动调整题目、草稿或解析区域宽度时引入；普通布局用 Grid/Flex |
| 拖拽 | dnd-kit | 尚未安装；排序、跨区域拖放等功能需要时引入；点击方格、滑块和普通输入不引入拖拽库 |
| 客户端状态 | Zustand | 尚未安装；跨页面共享可变状态确有需要时采用；组件局部状态保留 React |
| 数学交互 | 现有 animation-engine、math-core 与 SVG | 保留确定性步骤、判题与可重放数据，不以 UI 动画代替数学规则 |
| 账号与学习数据 | 现有 API、同步层、Cloudflare D1 | 服务端为权威来源；不将客户端 store 作为跨设备数据库 |

shadcn/ui 的 Nova 有不同底层组件实现。首次接入时固定一套底层组件与生成配置，提交 `components.json`、组件源码及依赖锁文件；后续沿用，不混用两套底层实现。配置以接入时核验的[官方安装文档](https://ui.shadcn.com/docs/installation/manual)为准。当前未创建生成配置，也未安装 Tailwind 或上述待引入库。

## 组件与设计语言

- 继续以 `apps/web/src/tokens.css` 为现有颜色、字号与间距的来源；接入 Nova 时建立统一映射，避免同页出现两套 token。蓝白主色、清晰题干和轻量边框保持一致。
- 页面只组合共享控件与业务组件。通用按钮、输入框、选择、对话框及反馈样式集中维护；涉及数学作图的业务组件保留在原有领域目录，不强行套进通用 UI。
- 每次迁移一个控件的全部调用点，清理旧封装和对应样式，再迁移下一个。引入新组件不能长期保留同用途的两套实现。
- 题目、输入与主要按钮构成主区域。默认只展示必要条件；答案、详细解析和分步图解按需展开。按钮直接写“提交”“下一题”“看解析”，减少重复提示、口号和无内容副标题。
- 平板主要点击目标至少 44px，提供清晰焦点和字段标签；拖拽有点击或键盘替代；减弱动效时仍能阅读完整推演。手机布局不新增验收工作。

## 依赖引入与替换

1. 先查现有共享组件、`package.json` 和 `pnpm-lock.yaml`，确认不能用现有方案直接满足功能。说明实际调用场景和为何需要新增依赖。
2. 只在使用该库的 workspace 包声明直接依赖，锁定精确版本，使用 pnpm 更新并提交唯一锁文件；共享版本保持一致。检查许可、维护情况、React 与构建兼容性和新增传递依赖。
3. 不引入第二套 UI、图标、动画、拖拽或客户端状态库。第三方组件间接引入重复能力时，检查是否可复用现有底层；必要例外在变更说明中写明范围和清理方案。
4. 替换现有库需迁移调用点、删除旧直接依赖和无用样式，再重新检查锁文件。第三方库源码定制纳入仓库，保留适用的许可和来源说明。
5. 变更后检查格式、类型、构建和相关交互。验证 PC 与平板的布局、焦点和触控；涉及作答、提示或状态迁移时，验证原有答案、错题和 D1 同步行为。

## 状态与动画边界

弹窗开关、当前输入等局部状态留在 React。若后续引入 Zustand，只承载跨组件客户端状态，并复用现有同步接口；不要额外持久化一套答题历史。切换账号必须清理身份相关状态，不能混合不同账号的缓存、草稿与待同步事件。

教学步骤、数学值和判题结果由现有契约与领域代码确定。Motion 只负责状态之间的视觉变化；暂停、前后步骤和减弱动效不能改变数学结果。新增 UI 库不应进入 math-core 或 Worker 的领域逻辑。
