# 数学智能教学平台产品与详细设计

版本：v1.0 · 日期：2026-10-19 · 适用：首期完整 V1，M1 按开发文档缩小内容范围

## 1. 产品约束与需求编号

首期面向使用指定版次教材的四年级学生、陪伴学习者和教师。学生主任务为“找到当前课 → 看懂 → 动手操作 → 试着做 → 得到提示 → 回顾”，后台主任务为“教材定位 → 制作 → 校验 → 审核 → 发布”。

| 编号 | V1 必须具备的需求 | 验收核心 |
| --- | --- | --- |
| REQ-01 | 教材首页与切换 | 默认首期教材；第二本数据接入无需改路由代码 |
| REQ-02 | 完整教材目录与课程 | 顺序、版次、活动、页码与映射表一致 |
| REQ-03 | 教学交互与静态降级 | 播放、暂停、单步、回退、重置、改参一致 |
| REQ-04 | 客观答题、分层提示、错题 | 服务端判分，重复提交不重复计入 |
| REQ-05 | 进度与复习 | 按人和教材隔离，完成与掌握分开 |
| REQ-06 | 内容后台与审核发布 | 草稿不可读，旧内容可追溯，可撤回 |
| REQ-07 | AI 配置与草稿生产 | 密钥不泄露，错误输出不能直接发布 |
| REQ-08 | 教材持续扩展 | 新版不覆盖旧版，导入可校验和回退 |
| REQ-09 | 课堂演示与可访问性 | 隐藏个人信息，触控/键盘均能完成操作 |

教师作业下发、学生排名、公开社区、语音对话、手写 OCR 自动判分和视频导出属于后续需求。单课演示模式纳入 V1，完整班级教学系统另行设计。

## 3. 首页与教材选择

### 3.1 首页布局

首屏从上到下：品牌与“我的教材 / 复习 / 学习记录”导航；当前教材卡；主要行动；教材目录。兼容与验收范围为 PC Web 和平板浏览器；桌面侧栏展示复习与最近学习，平板按可用宽度安排目录列数，不要求手机适配。首页不以通用聊天框、课程销量或功能宣传占据主要区域。

| 区域 | 内容与行为 |
| --- | --- |
| 当前教材 | 苏教版数学 四年级上册、2026 年第 1 版、封面/自制书名卡、“切换教材” |
| 主行动 | 新用户“从第一单元开始”；已学习用户“继续：上次课节”，显示单元和书内页 |
| 进度 | “已完成 X / Y 个学习节点”，Y 来自当前 release 的必修节点 |
| 单元目录 | 六单元按教材顺序，四活动插入原位置，末尾期末复习；按需展开课节 |
| 复习入口 | 当前教材“待复习 N 个知识点”，无记录时显示说明和示例 |
| 最近学习 | 课节、学习时间、保存状态；不显示排名 |

`GET /api/v1/home` 由服务端解析教材选择优先级：用户最近明确选择且可见的 edition → 系统默认 edition。首次访问和无偏好访客默认 `sj-math-g4-upper-2026-v1`。访客偏好保存在本地，仅作为查询候选；服务端仍检查可见性。切换教材不抹去旧进度，旧记录通过教材筛选查看。

默认教材不存在或被撤回时显示教材选择页并提示运营配置问题，不静默选一本不相关教材。只有一本时保留低强调的“当前教材”入口；多本时开放筛选。建设中内容显示状态且不可开始练习，不能把其题目数量计作可学数量。

### 3.2 学习页

顶部为“教材 → 单元 → 课节”及书内页码。主体为教学区和教具区，下方是当前步骤讲解及操作提示。学生按“情境 → 探索 → 归纳 → 例题 → 练习 → 小结”学习，允许返回任何已发布步骤。

例如面积课：先呈现 8×5 的长方形 → 学生摆一排单位方格 → 复制多排 → 统计每排数量、排数和总数 → 对应长、宽、面积 → 显示 `S=a×b` → 改变长宽并比较。此课依据书内 p.30；这个流程是平台教学设计，不冒充教材视频。

示范例题可直接展开解析；独立练习默认隐藏答案，提示分“关注条件 / 下一步 / 详细解释”。学生选择看完整解析后标记为“已看解析”，本次表现不计入独立正确证据。下一课入口出现在课节小结，不用看完动画的时长判断是否理解。

### 3.3 页面状态

所有主要页面定义 loading、empty、error、ready。学习页额外处理资源失效、内容撤回、版本更新、离线未保存；练习页处理 submitting、graded、pending_manual、submission_failed。网络重试保持输入；切换课节前保留未提交草稿并明确保存状态。可重试错误提供动作，业务错误说明可行下一步。

## 4. 视觉与交互规范

采用明亮、清晰的教材式学习界面。UI/UX 技能中的儿童学习类建议支持清楚层次、触控反馈和色彩区分；本项目选用平面图形与轻量卡片，避免营销首页或强装饰挤占教具空间。

| 项目 | 设计规范 |
| --- | --- |
| 字体 | 系统中文无衬线字体优先；不依赖海外字体加载；公式按需加载本地字体 |
| 字号 | 学生正文 18px 起、行高约 1.65；后台正文 14–16px；投屏 24px 起 |
| 颜色 | 主色 `#2563EB`、正文 `#0F172A`、次正文 `#475569`、白色内容区、浅蓝背景；黄用于提示，状态同时配文字与图标 |
| 尺寸 | 学生主要触控控件至少 44×44px，相邻控件留 8px；数字键盘更大 |
| 布局 | 验证 375/768/1024/1440px；复杂表格局部滚动，正文无横向滚动 |
| 可访问性 | 正文对比度目标 4.5:1；可见焦点、字段标签、错误定位、状态播报 |
| 交互替代 | 拖动点、格子或滑块均提供点击/键盘/数值输入替代；不只依赖颜色或 hover |
| 动效 | UI 反馈约 150–250ms；教学动画由步骤驱动，可调速、暂停；减弱动效时保留状态变化与解释 |

图形单位是数学坐标，不是 CSS px。量尺教具需明确“示意比例”，不能要求学生用真实尺量屏幕得到教材中的厘米值。投屏模式不显示账号、错题统计和学生自由文本。

## 5. 领域模型与存储设计

### 5.1 通用约定

主键为服务端生成的文本 ID；业务时间保存 UTC ISO-8601，前端按用户时区显示。JSON 内容必须通过带版本的 Schema；金额用最小货币单位整数，精确有理数用分子/分母字符串表示。题目大整数使用十进制字符串传输，后端 BigInt 计算，禁止静默超出 JavaScript 安全整数范围。

稳定实体与不可变修订分离。已发布修订只读，修改创建新修订；草稿乐观锁 `lockVersion`。删除使用归档/撤回，存在学习记录引用的数据不物理级联删除。

### 5.2 数据字典

以下为逻辑表基线，字段列省略通用 `id/created_at/updated_at`；正式 SQL 迁移在 T02 实现。`FK` 必须落实为外键或有明确跨资源验证，不只依赖前端。

| 表 | 关键字段 | 约束及索引 |
| --- | --- | --- |
| users / user_identities | display_name、status；user_id、issuer、subject | 身份 `(issuer,subject)` 唯一 |
| user_roles / sessions | user_id、role；token_hash、expires_at、revoked_at | 角色联合唯一；会话到期索引，仅存 token 哈希 |

教学正文采用受限块结构：`paragraph`、`math`、`imageRef`、`sceneRef`、`exampleRef`、`practiceRef`、`checkpoint`、`summary`。引用必须通过发布清单解析，不允许嵌任意 HTML 或数据库查询。

### 5.3 关键一致性

目录树编辑只有后台可见；发布清单包含节点快照，因此草稿重排不会立即影响学生。`active_release_id` 必须指向同 edition 的有效 release，应用层与数据库约束共同保证。

题目修订 → answer_key → solution → scene 的完整依赖闭包必须全部校验。修改题干会产生新题目修订，不能继续引用旧答案的审核结论。跨教材复用题目需复制为新教材题目并记录 `derived_from_revision_id`，再审核；跨教材共享数学规则和动画模板无需复制。

客观判题时把 attempt、学习事件和幂等响应在同一 D1 batch 内写入；复杂统计异步投影，事件为事实来源。任务创建与 outbox 同批写入；Workflow 创建失败时重新派发同一 job，不重复创建内容草稿。

列表使用基于 `(created_at,id)` 的游标，默认 20、最大 100 条。主要复合索引包括目录 `(edition_id,parent_id,sort_order)`、作答 `(user_id,session_id,created_at)`、学习事件 `(user_id,edition_id,created_at)`、任务 `(state,created_at)`。重题检测用规范化题干哈希做精确提示，近似题由编辑判定，不自动删除。

## 6. 内容生命周期与发布

修订状态为 `draft → validating → in_review → approved`，验证失败回到 `draft` 并附报告；审核退回为 `changes_requested`，修改后重新验证。发布是 release 的行为：`building → validated → active → superseded`，并支持 `withdrawn`。内容批准不等于学生可见。

编辑不能单独审核自己的内容；首期至少有不同人的编辑与审核账号。管理员可配置角色，但不得以 UI 隐藏按钮代替服务端权限。数学验证、教研审核及预览报告均绑定内容哈希，发布时复检。

发布使用 `expectedActiveReleaseId` 条件切换。撤回先停用 release/edition，再失效缓存；回退激活已验证的旧清单，保留撤回原因及审计。用户正在做的练习会话固定 release；被替代但仍有效的旧版可继续，被撤回的内容停止新提交并提供可保留的草稿和重开练习入口。

## 7. API 契约

统一前缀 `/api/v1`。成功体为 `{data, requestId}`；分页体在 data 内包含 `items,nextCursor`；失败体为 `{error:{code,message,fieldErrors?,retryable},requestId}`。服务端 JSON 字段用 camelCase，数据库 snake_case。所有路径 ID 都是资源 ID，不能任意拼 R2 key。

| 方法及路径 | 用途 | 权限/关键行为 |
| --- | --- | --- |
| `GET /home?editionId=` | 首页聚合 | 访客可用；个人数据响应不可共享缓存 |
| `GET /textbooks?grade=&volume=&cursor=` | 教材列表 | 只返回可见版次 |
| `GET /textbooks/:editionId/catalog?releaseId=` | 目录快照 | 返回 edition、release、节点状态 |
| `GET /textbooks/:editionId/lessons/:lessonId?releaseId=` | 课节教学包 | 只返回当前清单引用内容；题干与隐藏答案分离 |
| `PUT /me/current-textbook` | 保存教材选择 | 学生；验证 edition 可见 |
| `GET /me/progress?editionId=` | 学习记录 | 仅本人 |
| `POST /practice-sessions` | 创建练习 | 学生；服务端固定教材、release 与选题 |
| `POST /practice-sessions/:id/attempts` | 提交答案 | 本人；Idempotency-Key 必填 |
| `POST /practice-sessions/:id/hints` | 分层提示 | 本人；记录提示级别和是否揭示答案 |
| `POST /lessons/:id/checkpoints` | 保存教学操作检查点 | 本人；受限快照，不能传得分 |
| `GET /me/mistakes?editionId=&cursor=` | 错题 | 仅本人；不跨教材混合推荐 |
| `POST /feedback` | 内容纠错 | 登录用户；绑定内容修订 |
| `POST /admin/textbooks/imports` | 建立导入草稿 | 编辑；manifest/资源验证结果可查询 |
| `POST /admin/content/:type` | 创建课节/题目等草稿 | 编辑；输入 schemaVersion |
| `PATCH /admin/content/:type/:id` | 编辑草稿 | 编辑；`If-Match` 乐观锁，不修改已发布修订 |
| `POST /admin/revisions/:id/validate` | 确定性验证 | 编辑/审核者；返回结构化报告 |
| `POST /admin/revisions/:id/reviews` | 审核结论 | 审核者；校验作者与 hash |
| `POST /admin/releases` | 构建发布清单 | 审核者；完整依赖闭包校验 |
| `POST /admin/releases/:id/activate` | 激活/回退清单 | 审核者；expectedActiveReleaseId |
| `POST /admin/releases/:id/withdraw` | 撤回 | 审核者；原因必填 |
| `POST /admin/generation-jobs` | 解答/场景/题目生成 | 编辑；202 返回 jobId，预算预留 |
| `GET /admin/generation-jobs/:id` | 查询进度 | 有该教材编辑权限者 |
| `POST /admin/generation-jobs/:id/cancel` | 请求取消 | 创建者/管理员；正在进行的外部请求不保证取消计费 |
| `POST /admin/ai-providers` | 配置模型连接 | 管理员；回包仅密钥掩码 |
| `POST /admin/ai-providers/:id/test` | 测试连通及能力 | 管理员；最小请求，记录消耗 |

身份回调、会话注销和资源读取属于基础设施 API；私有资源读取同样校验身份、用途和 edition 状态。内容检索/题库管理接口使用同一分页、过滤和授权规范，OpenAPI 在开发 T01/T02 中生成。

### 7.1 作答示例

以下 ID 为设计样例，字段格式是契约约定：

```http
POST /api/v1/practice-sessions/ps_demo/attempts
Idempotency-Key: 8b55ff13-0704-477d-a86b-43515b152a2f
Content-Type: application/json

{
  "itemId": "item_01",
  "attemptNo": 1,
  "answer": {"kind": "division", "quotient": "6", "remainder": "4"}
}
```

```json
{
  "data": {
    "attemptId": "attempt_demo",
    "gradingState": "graded",
    "result": "correct",
    "score": 1,
    "feedback": "商和余数都正确，可以再用乘法验算。",
    "saved": true
  },
  "requestId": "request_demo"
}
```

对应设计例为 172÷28；服务器根据 session item 获取题目与规则，不信任客户端的答案版本。相同键和请求体重试返回相同结果；键相同体不同返回 `409 IDEMPOTENCY_CONFLICT`。会话并发相同 attemptNo 依唯一约束决胜，不能重复创建学习证据。

### 7.2 错误与限流

400 结构错误，401 未登录，403 无权限，404 不存在/不可见，409 版本或幂等冲突，410 内容撤回，422 数学参数或业务语义错误，429 配额不足，503 临时不可用。429/503 可返回 Retry-After；前端不自动重试非幂等写入，写入重试必须复用原键。

普通读取按匿名/IP 与已登录用户配额，AI 额外限制用户/教材/任务并发和日成本。具体阈值是运维配置，经压测确定；不能用客户端禁用按钮作为限流实现。

## 8. 数学判题与学习反馈

| 题型 | 结构化输入 | 判题规则 |
| --- | --- | --- |
| 单选 / 多选 | optionIds | 选项 ID 集合比较，拒绝题外 ID |
| 整数填空 | 十进制字符串 | 规范化全角和首尾空格，拒绝非法字符；BigInt 精确比较 |
| 除法商余数 | quotient、remainder | 两项分别比对，保证 `0≤r<d`，不得把余数改写成小数 |
| 数量与单位 | value、unit | 长度/面积/时间等维度匹配后换算；明确是否允许等价单位 |
| 竖式过程 | 结构化格位与步骤 | 校验位值、部分积/差、落位；结果与过程分开反馈 |
| 混合算式 | 受限表达式 AST 或 token | 白名单整数、四则、小/中括号；AST 求值，拒绝任意代码 |
| 操作题 | 网格/节点/量值快照 | 验证操作目标与最终状态，不能只信客户端 completed=true |
| 开放实践 | 表格、文字或作品引用 | `pending_manual`，给量规反馈，不自动宣判唯一答案 |

每题持有独立 `gradingPolicy`：结果题允许等价算式，过程题还要求表达合法步骤；单位要求和容差显式设置。首期普通整数题不采用浮点近似相等。四舍五入基于整数除余实现，覆盖进位边界；面积网格用单位格坐标与边共享计数，避免依屏幕像素估算。

完成度与掌握状态分开：课节完成要求关键 checkpoint 与练习尝试完成；掌握状态暂定为“证据不足 / 学习中 / 初步掌握 / 待巩固”。默认规则：至少 5 道不同逻辑题目的独立客观作答、跨至少 2 次练习会话，最近最多 10 次有效证据正确率达到 80% 可标“初步掌握”；低于 60% 标“待巩固”，其余“学习中”。不足 5 次为“证据不足”。这些是可调产品规则，不声称精确测量认知能力。

同题重复尝试、看过详细解答、AI 提供答案、手工未审核的开放题不计独立正确证据。按稳定 questionId 去重，只计每题首次有效独立作答；同题修订不能额外凑足样本数量，已知答案错误的修订证据可被标记无效但保留原始记录。证据按知识点权重关联。复习优先当前教材的错误标签与前置知识；显示推荐理由，例如“上次把平方分米换算成平方厘米时进率用错”。不以观看时间推断掌握。

课节修订增加 `objectiveVersion`：仅改错字或插图不改变目标版本，保持完成状态；改变必学目标或检查点时提升目标版本，旧学习记录显示“已完成旧版，新增内容待学”，不无声清空历史。目录分母由当前 release 决定，新增节点导致比例变化时说明原因。

## 9. 动画模板与 DSL

### 9.1 模板注册表

| templateId | 主要教学用途 | 关键不变量 |
| --- | --- | --- |
| `division-groups` | 等份分组、商余数 | 总量守恒，余数小于除数 |
| `long-division` | 试商、调商、位值 | 每步被除部分 = 除数×局部商 + 余量 |
| `perimeter-unfold` | 描边与边展开 | 线段展开前后长度和一致 |
| `area-tiling` | 单位方格与面积公式 | 行×列 = 格数，格子不重叠 |
| `perimeter-area-compare` | 定面积/定周长比较 | 约束保持，边界条件明确 |
| `quantity-relation` | 价格/速度/倍数关系 | 维度正确、条件与未知量一致 |
| `operation-order` | 混合运算步骤 | 只化简当前合法子表达式 |
| `place-value` | 数级、读写、满十进一 | 数值守恒，数字与数位一致 |
| `rounding-number-line` | 近似数 | 精确值、保留位与边界一致 |
| `long-multiplication` | 三位数乘两位数 | 部分积按位累加 |
| `calculator-explorer` | 计算器与规律记录 | 输入、规则、输出可回放 |
| `measurement-lab` | 旅游预算、单位背景、大数推算 | 量纲、数据来源与估测标签完整 |

12 个模板为目标模板族，M1 先实现 `division-groups`、`long-division`、`area-tiling`；每个模板必须有静态等价教学内容。无合适模板时退回静态步骤，不生成任意代码凑出动画。

### 9.2 协议 v1

根字段：`schemaVersion`、`sceneId`、`templateId`、`templateVersion`、`sourceRefs[]`、`parameters`、`controls[]`、`steps[]`、`checkpoints[]`、`fallback`。每个 templateId 使用独立的 discriminated union Schema，`additionalProperties=false`。sourceRefs 含 editionId、PDF 页和书内页，发布时再解析成源资源 ID。

以 area-tiling 为例：parameters 包含整数 `columns/rows`、枚举 `unit=cm`；列 1–20、行 1–15、单位格总量≤300。controls 为已声明参数的 integer 控件，范围只能缩小模板范围。steps 含唯一 id、枚举 action、0–10000ms durationMs、narration；动作仅 `outline`、`fillFirstRow`、`fillAllRows`、`showFormula`。插值占位符只允许 `columns/rows/area/unit/areaUnit`，由引擎计算 area，模型不能传入 area 覆盖。

完整示例见 [area-tiling.scene.example.json](./specs/area-tiling.scene.example.json)。模板注册表必须声明动作的前置条件、效果和可用插值变量；未知模板、动作、变量、源文件或越界参数拒绝，不忽略后继续播放。

全局预算初值：场景 JSON ≤128KB、步骤≤40、总标称时长≤180 秒、控件≤8、文字每段≤500 字符。模板可进一步收紧。题目内容引用/素材必须是已审核 ID，不接受远程 URL、事件脚本、任意 SVG/HTML 或表达式执行函数。

### 9.3 状态机与交互语义

`idle → playing ↔ paused → completed`；任何状态可 reset 到初始。步骤通过纯函数 `reduce(scene, parameters, stepIndex)` 重建状态；动画只是从前状态到新状态的呈现，不作为数学真值来源。回退、拖动时间轴和刷新恢复必须得到相同状态。

改参时暂停并从第一步重建，清除当前未完成 checkpoint；已提交的历史练习不改写。reset 保留默认参数而非最后拖动值。速度仅改变呈现时长，不能改变数值。切换场景清理计时器，页面不可见自动暂停；减少动效时直接呈现步骤目标状态。

检查点 `kind=integer` 指定 prompt、expectedVariable、triggerStepId。客户端可即时反馈练习体验，但正式记录由服务端用相同模板规则和参数重新计算。生成式文字涉及数值时优先插值，避免改参后旁白仍显示旧答案。

## 10. AI 工作流与教学约束

Provider Adapter 输入统一为 messages、outputSchema、limits、timeout 和任务上下文，输出 normalizedResult、usage、finishReason。服务商能力分别探测并存储，如 JSON Schema、流式、上下文长度；不能把“兼容接口”视为全能力兼容。

本期任务：`explainDraft`、`questionDraft`、`sceneDraft`、`rewriteHint`。每任务上下文包含 editionId、releaseId、课节修订、教材定位、允许知识点/方法、题型 schema、单位和数值约束、年龄适宜语言、已审核提示。首期按课节/知识点精确检索，后续语义检索仍先按教材版次过滤。

生成步骤：抽取条件与目标 → 选择允许方法 → 得到答案和可展示教学步骤 → 规则验证 → 适龄改写 → 模板参数与步骤 → 内容验证 → 新草稿。教学步骤为简洁的可核验解法，不要求保存模型内部推理。每步含 `id,rule,inputs,result,explanation,hint,validationStatus,sceneStepRefs`。

`validationStatus` 为 `passed/failed/unsupported`。unsupported 不能伪装通过，例如自由文字证明、开放作品质量依人工审核。确定性验证不通过最多一次带错误报告的修正，仍失败转人工；Schema 错误最多一次修复；429/5xx 按明确退避最多两次重试。整个任务超时、次数和预算设置硬上限。

模型任务状态：`queued/running/validating/needs_review/succeeded/failed/cancel_requested/cancelled`。`needs_review` 表示产出草稿但未完成审核，`succeeded` 仅表示任务成功处理，不代表课程已发布。后台展示细分步骤；轮询 2 秒起逐步退避到 10 秒，后台页面隐藏时暂停。

即时提示只在当前练习内给出，不从别的教材抽取超纲方法；先提供已审核提示，可选模型改写只对已审核事实作表达调整。未经审核的生成文字明确标注，无法验证时返回原提示。AI 不能写正式成绩、改课节完成状态、配置 provider 或自动批准内容。

## 11. 教材导入与内容后台

后台向导为：元数据与来源 → 文件完整性/解析 → 页码映射 → 目录结构 → 课节知识点 → 讲解/练习/场景 → 检查报告 → 审核发布。首期允许本地内容文件导入，不依赖开发完整在线排版器。

导入采用 `schemaVersion + editionId + source.sha256 + packageVersion`，并计算规范化整个内容包的 `packageHash`；同一身份且包哈希完全相同返回已有结果，同一版本号却内容不同则拒绝并要求提升 packageVersion。同版新包创建草稿差异，不原地改 active release。报告列出缺失引用、未映射页、重复 ID、跨教材引用、无答案题、未通过审核和资源权限不足。

审核页左侧教材页或来源定位，中间平台讲解和步骤，右侧验证报告与差异。可切换学生预览、触控预览、静态降级；审核前必须实际执行互动任务。批量“通过”仍需对每个修订记录独立审核人、内容 hash 和维度，不因 AI 自检通过自动授权。
