# 数学智能教学平台开发实施

版本：v1.0 · 日期：2026-10-19

## 1. 当前状态与实施顺序

本文件的规划基线建立时，工作区只有首期教材 PDF 和设计文档。当前已实现的代码、脚本、题库与验收边界见[开发进展](./05-开发进展.md)，实际可用命令见[项目说明](../README.md)。下文仍保留完整阶段规划，不表示所有模块均已完成。

开发按照“最小教学闭环 → 模板与后台 → 全册内容 → 第二教材验证”推进。先让第一单元和长方形面积课真实可学，再扩展至全册；AI 接入建立在确定性判题、内容修订和发布流程之上。

## 3. 工程初始化与开发约定

### 3.1 初始化

1. 检查项目和上级目录的开发约定，若尚未初始化版本控制则建立仓库和忽略规则。
2. 选用当前 Cloudflare React + Vite 模板，在 `apps/web` 初始化并接入 Hono，避免在项目根目录创建第二套互相冲突的结构。模板入口以[官方指南](https://developers.cloudflare.com/workers/framework-guides/web-apps/react/)为准。
3. 选择满足 Vite/Cloudflare 工具链要求的 Node LTS 与 pnpm 版本，将精确版本写入工具版本文件和 packageManager。锁定依赖并提交 lockfile，不在 CI 随意安装 latest。
4. 建立 contracts、math-core 与 database 包，再实现 /health、错误格式和 requestId。
5. 建立 local/staging/production 三套资源配置；开发使用本地 D1/R2 模拟绑定和 mock AI，不能默认连接正式学生数据。

建议根脚本契约如下；T01 完成后才可执行：

| 约定命令 | 应实现的行为 |
| --- | --- |
| `pnpm dev` | 启动前端与 Worker 本地开发环境 |
| `pnpm lint` / `pnpm typecheck` | 风格、类型、包依赖边界检查 |
| `pnpm test` | 数学与协议单元测试 |
| `pnpm test:integration` | Worker API、数据库、鉴权与幂等 |
| `pnpm test:e2e` | 学习、练习、编辑、发布核心路径 |
| `pnpm content:validate --edition <id>` | schema、来源、页码、引用、数学与覆盖报告 |
| `pnpm content:import --edition <id> --target local` | 幂等导入到本地，默认不发布 |
| `pnpm build` | 类型通过后构建前端和 Worker |
| `pnpm deploy:staging` | 定向发布预发布环境；不隐式发布生产 |

开发阶段采用小粒度提交，代码与契约、迁移、示例和对应文档一起变更。格式化由统一工具完成；禁止把本地绝对路径写入生产 manifest。

### 3.2 配置与资源

| 绑定/配置 | 用途 | 敏感性 |
| --- | --- | --- |
| `DB` | D1 数据库 | 资源绑定 |
| `SOURCE_BUCKET` | 私有教材、草稿资源 | 私有，关闭公开访问 |
| `PUBLIC_ASSETS` | 已审核原创或授权图片 | 资源白名单，不混入原始 PDF |
| `CONTENT_GENERATION` | Workflow 类绑定 | 资源绑定 |
| `OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_REDIRECT_URI` | 登录来源 | 普通服务端配置 |
| `OIDC_CLIENT_SECRET` | 登录客户端密钥 | Secret |
| `SESSION_SIGNING_KEY` | 会话/签名用途 | Secret，轮换版本化 |
| `PROVIDER_KEK_V1` | 模型密钥加密主密钥 | Secret，禁止复用会话密钥 |
| `AI_DAILY_BUDGET_MICRO` | 日预算上限 | 运维参数 |
| `APP_ENV`、`LOG_LEVEL` | 环境与脱敏日志级别 | 非敏感 |

静态默认教材属于 `site_settings.defaultEditionId`，不编译进前端。环境资源 ID 不使用示例占位值直接部署；Worker compatibility_date 在首次部署时按实际验证日期固定，后续单独升级。

本地 Secret 文件加入忽略规则；前端所有 `VITE_*` 变量均视作公开信息，不存任何凭据。开发 seed 身份仅在 local 有效；staging/production 启动时断言调试身份关闭。

工期为小团队的初始估算，不是承诺。假设具备前后端开发与独立数学教研/审核人员，内容制作与程序开发可并行安排，实际进度以验收结果为准。

| T07 学习闭环 | 课节页、练习会话、答题、提示、进度、错题 | T03–T06 | 从首页学习到复习全链路通过 |

## 5. 首个可运行切片

验收路径为：打开首页看见正确教材 → 进入第一单元试商课 → 拖动/选择试商并观察乘回比较 → 提交商和余数 → 获取分层提示 → 查看保存的结果 → 从首页继续学习 → 在错题页复习。另一路验证 U02-L05 的铺格到面积公式，并在改参后同步更新图形、文字与检查点。

M1 不要求完整 AI 服务才能验收，使用人工审核内容；但数据库、内容 revision 和题目 release 必须从第一天保留，不能先用无版本 JSON 直接接学生数据再事后补关系。

内容发布的演示链：编辑提交新题 → 数学验证 → 不同审核者审核 → 构建发布 → 学生可见 → 再修改题目 → 老练习仍能回看原修订 → 撤回错误内容后新请求不再读取。

## 6. 教材内容生产操作规程

1. 计算 PDF 哈希，读取版权页、目录、总页数；同名不同版按不同 edition 处理。
2. 保留源 PDF；提取文字并记录解析警告。逐页登记 `pdfPage / printedLabel / kind / parseStatus`，图形和公式做图像复核。
3. 导入教材目录。使用本次 [manifest 示例](./specs/textbook-manifest.example.json)作为结构起点，生产导入器展开显式页映射并生成报告。
4. 按 [课程映射](./04-首期教材与课程映射.md)制作课节，不将课节拆分建议误称为教材官方课时。
5. 每题标记来源类型、知识点、题型、评分策略、允许方法和答案；有改编必须说明。
6. 生成或人工撰写解析，运行 math-core；为不支持自动验证的内容标 unsupported，交人工审核。
7. 选择模板，填写参数和步骤；检查改参、回退、触控与静态版本。
8. 数学、教材一致性和教学交互分别审核，生成内容覆盖报告和发布清单。

生产导入不能把 `sourceLocalPath` 发送给学生，也不能直接映射为公开 URL。扫描修订更换后比较页映射，旧锚点保留；不只替换文件名。若源文件不能稳定解析，先制作预处理副本并记录父文件哈希与处理方式，原文件保持不变。

## 7. 数学与内容验证

### 7.1 确定性测试

| 编号 | 输入/场景 | 预期 |
| --- | --- | --- |
| MATH-01 | `172÷28` | 商 6、余数 4；试商 5 的余数 32 应触发调商 |
| MATH-02 | `156÷12`、`840÷40`、`612÷30` | 分别 13、21、20 余 12；商位与 0 正确 |
| MATH-03 | 除数 0、余数等于除数、负值越界 | 拒绝或判错，不能崩溃 |
| MATH-04 | 长 8、宽 5，单位 cm | 面积 40 cm²、周长 26 cm；文字随参数变化 |
| MATH-05 | `1dm² → cm²`、`1m² → dm²` | 均为 100；拒绝 cm 与 cm² 混换 |
| MATH-06 | 周长 16，正整数边长的长方形 | 可枚举 1×7、2×6、3×5、4×4；最大面积 16 |
| MATH-07 | `18+18×2-6` | 48；高亮乘法后再从左往右 |
| MATH-08 | `525÷[(81-56)×3]` | 7；括号嵌套顺序正确 |
| MATH-09 | `80÷4×2` | 40，不能改成除以 8 |
| MATH-10 | `100010001`、`2006000000` | 正确分级、读零规则，不能丢中间位 |
| MATH-11 | 384204、386685 按万取近似 | 38 万、39 万，使用约等号 |
| MATH-12 | `99995000` 按万取近似 | 10000 万，跨位进位正确 |
| MATH-13 | `128×16`、`106×20` | 2048、2120，部分积和占位正确 |
| MATH-14 | 70 米/分 × 4 分 | 280 米；单位不兼容时先转换或拒绝 |

增加性质测试：对合法除法参数验证 `n=dq+r` 与余数范围；面积等于格数、周长等于外露边数；单位往返转换保持值；表达式逐步求值与最终求值一致；同一场景反复重放稳定。性质测试不得只用实现本身生成“正确答案”，代表例和边界答案需独立手工核对。

### 7.2 内容校验

每个必修节点必须有教材定位、目标、教学区块、练习/活动、静态备选和审核；每个客观题必须有独立评分规则；所有 sourceRefs 页码不越界、版次匹配。发布依赖闭包里不能存在 draft、failed、unsupported 且未人工确认的内容。

模板 Schema 通过只是第一关，必须继续验证数学不变量、步骤前置条件和数值旁白。对 AI 样例混入“忽略规则”“外部脚本地址”“改变成绩”等文本，确认它们只作为数据处理并被相应约束拒绝。

### 7.3 AI 离线评测

建立首期至少 60 个经人工审校的样例，六单元各至少 8 个，另含活动和异常输入。覆盖错误前提、信息不足、单位冲突、超纲方法、无合适模板、provider 超时和非 JSON 回包。评测库不等于正式题库。

报告分别列答案正确率、步骤规则通过率、来源与范围符合率、Schema 通过率和需人工修订比例，不把模型自评算作通过。发布内容正确性要求人工/程序验证全部通过；AI 草稿首轮通过率只用于改进流程，不降低发布门槛。

## 9. CI 与部署

PR 检查按顺序执行：依赖锁定安装 → lint/typecheck → 数学和 schema 测试 → 本地数据库迁移与 API 集成 → 内容包校验 → 构建 → 核心 E2E。只要改变判题、权限、发布或教材内容，就运行对应回归；纯文字调整运行文档链接与内容来源检查即可。

staging 使用独立 D1/R2/Secret，数据采用测试账号。确认 `/api/*` 不落入 SPA 页面、页面深链刷新正常、错误不暴露堆栈或 key。部署报告必须记录 git commit、依赖锁版本、schema 迁移号、Worker 版本和 content releaseId。

生产发布顺序：核对备份 → 运行向后兼容迁移 → 发布兼容新旧字段的服务 → 上传不可变资源 → 导入已审核内容 → 验证清单 → 切换 release 指针 → 烟测首页、练习和权限 → 观察指标。初次发布仍需先把完整发布候选在 staging 验收，不能把生成草稿直接当线上 seed。

回退分三类：应用版本回退到兼容数据库的旧版本；课程回退到旧 release；数据破坏通过备份恢复及审计重放处理。破坏性 schema 改动采用 expand/contract 两阶段，旧代码停止使用后才删旧字段。任何远程部署命令必须显式目标环境，避免本地开发脚本误操作生产。

## 10. 运行与维护

后台每日关注判题失败、保存失败、任务积压、模型成本、内容反馈和覆盖缺口。严重数学错误立即撤回相关修订，定位受影响作答，并给出带版本的纠错说明；不无声修改历史正确答案。

定期演练从备份恢复 D1 与发布清单，校验 R2 对象哈希可取得。记录恢复用时及丢失时间范围，对照 RPO/RTO 目标。账号删除请求先停用身份，再清除可识别学习数据并处理投影和缓存；匿名汇总和审计保留规则由运营确定。

内容维护不依赖开发者手写页面。新增教材日常流程由编辑完成目录/课节映射，开发只在出现新模板、新题型或新数学规则时介入。每次教材升级输出差异报告：章节变化、页码变化、课节迁移、可复用内容和必须重审的部分。

## 11. 完成定义

M1 完成：6 个试点节点有来源和已审核内容，用户可学习、操作、答题、保存、复习；后台可编辑审核与发布；三种模板及安全边界通过测试。

V1 完成：六单元、四活动和期末复习全部覆盖，35 个拟定节点均有有效学习/实践内容；关键数学测试和 E2E 全部通过；12 个模板族达到各自验收；AI 失败可降级；第二教材隔离演练通过；备份恢复、部署和使用地区的网络测试形成报告。节点拆分若调整，必须同步映射表与覆盖验收，不机械追求数字。

正式实施仍需在对应阶段落实：实际身份提供商、部署域名及区域访问方案、教研审核负责人、资源公开使用范围、模型服务及预算。上述配置不妨碍先建设本地闭环，但上线候选必须提供具体配置及验证结果。
